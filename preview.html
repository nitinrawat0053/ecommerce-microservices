🔄 Order Flow
User places order → Order Service creates order + outbox events ↓ (outbox worker polls every 5s) ┌────────┴────────┐ ↓ ↓ ORDER_CREATED ORDER_PLACED PAYMENT_INITIATED ↓ ↓ ↓ Product Service Cart Service Payment Service (reduce stock) (clear cart) (create Razorpay order) ↓ Payment verified / webhook ↓ PAYMENT_SUCCESS / PAYMENT_FAILED ↓ Order Service (confirm/cancel) Notification Service (email/SMS/WhatsApp)
🏗️ Design Patterns

📋 Transactional Outbox

Events written to MongoDB within the same transaction as domain data. A polling worker publishes them to RabbitMQ. Guarantees exactly-once delivery.

🔄 Retry + DLQ

Failed messages → retry queue (5s TTL) → after 3 attempts → dead letter queue. Applied to notifications and payment flows.

🔐 API Gateway Pattern

Single entry point handles JWT verification, role-based access, and forwards identity headers to downstream services.

⚡ Redis Caching

Product listings cached with 5min TTL. Cart cached with 1hr TTL. Cache invalidated on mutations.
